什麼是 CP-SAT 求解器？

OR-Tools 的 CP-SAT 是一款基於約束編程（Constraint Programming）的求解器。不同於傳統的啟發式算法（如遺傳算法），CP-SAT 通過「約束傳播」與「衝突導向搜索」，能在毫秒級別給出確定的最優解或可行解。

1

定義決策變數

我們需要設定「未知的決策」。在您的代碼中，決策是布林變數：某老師在某時間是否教某班。這是一個龐大的 4D 高維布林空間。

2

宣告限制條件

將現實中的規則翻譯為數學等式或不等式（例如：同一個老師同時間只能在一處）。求解器會透過這些限制大幅剪枝（Prune）搜索空間。

3

執行尋優與求解

求解器利用先進的 SAT（命題可滿足性）技術搜索。若存在解，它能給出一個確定值為 0 或 1 的變數矩陣，這便是最終的課表。

課表設計的維度模型：4D 變數張量

在電腦科學中，我們習慣將複雜問題抽象化。這段排班代碼建立了一個高維矩陣，這在空間中可以被理解為一個 4D 的座標網格：

T
Teachers (老師)

7 位 (0 至 6)

中文、英文、數學、生活、宗教、資源、參觀

C
Classes (班級)

5 個 (A, B, C, D, E)

每班一週所需學科節數皆固定且對應

D
Days (天數)

4 天 (Day 1 至 Day 4)

一個小型的四天循環教學日程表

P
Periods (節數)

6 節 (第 1 至第 6 節)

每天有六堂課，被「小息」分割為 L1-L3 和 L4-L6

總變數規模與狀態空間計算

在代碼中，變數 x[(t, c, d, p)] 的總個數為： 7 (T) × 5 (C) × 4 (D) × 6 (P) = 840 個布林變數。 如果使用簡單的暴力破解法，可能的狀態組合為 $2^{840}$ 達極天文數字，這就是為什麼必須借助 CP-SAT 求解器來進行深度搜索與剪枝。

代碼逐段深度拆解

我們將您的 Python 排班代碼分割為五大核心模組，並以計算機科學的視角為您講解底層運作機制。

MODULE 01 資料定義與黑名單矩陣

基礎資料結構與時間阻斷

這段程式碼首先定義了常規的物理空間常數。最有趣的是 class_available 字典：

這是一個典型在 CS 中使用的「稀疏陣列表示法」。我們用一個以多元組 (c, d, p) 為鍵的雜湊表（Hash Map）預先定義哪些時段是「不可用」的（例如開學禮、測驗、評估等）。

設計亮點
這裡的 1 代表可行，0 代表不可行。此資料結構便於在後續約束條件宣告中直接過濾。 
# 基礎資料定義
classes = ['A', 'B', 'C', 'D', 'E']
num_classes = len(classes)
num_teachers = 7
num_days = 4
num_periods = 6

# 老師科目與每班所需節數 (0:中文, 1:英文, 2:數學...)
teacher_requirements = {0: 2, 1: 2, 2: 2, 3: 2, 4: 1, 5: 1, 6: 1}

# 初始化時間可用表，並將固定活動時段設為 0 (不可排)
class_available = {}
for c in range(num_classes):
    for d in range(num_days):
        for p in range(num_periods):
            class_available[(c, d, p)] = 1

# 設定不可排課的固定活動 (如開學禮、評估等)
class_available[(c, 0, 0)] = 0  # 舉例：Day 1, 節數 0 為開學禮
MODULE 02 變數註冊與模型實例化

將決策抽象為模型變數

我們利用 model.NewBoolVar 來為每個狀態註冊一個布林變數。

在底層，OR-Tools 的 CP-SAT 求解器會將這些變數鏈接到它內部的 SAT 解算引擎。每個布林變數在求解完成後，都會分配到一個二進位值（0 或 1）。

這裡我們為變數傳入了唯一的名稱字串：f'x_{t}_{c}_{d}_{p}'。這對於求解器在輸出錯誤報告或診斷時非常關鍵，也有利於未來調試。 
model = cp_model.CpModel()

# 建立 4D 布林變數矩陣
x = {}
for t in range(num_teachers):
    for c in range(num_classes):
        for d in range(num_days):
            for p in range(num_periods):
                x[(t, c, d, p)] = model.NewBoolVar(f'x_{t}_{c}_{d}_{p}')
MODULE 03 硬性約束與物理物理不可能性排除

設定不可觸碰的「紅線」

這些約束條件是用來保障排班在物理現實中的「合理性」：

  • (A) 班級佔用時：若 class_available 標記為 0，則利用 model.Add(x == 0) 宣告所有老師皆不可排課。
  • (B) 老師不分身：在任何特定的 (d, p) 下，所有班級 c 的決策變數和必須 $\le 1$。我們使用優化性能的 model.AddAtMostOne(...) 方法。
  • (C) 學生不分身：同理，同一 (d, p) 下一班只能排一位老師。
  • (D) 教學節數要求：每班一週內分配給老師 t 的節數總和必須恰好等於 req。
# (A) 固定活動時，不排任何課
for c in range(num_classes):
    for d in range(num_days):
        for p in range(num_periods):
            if class_available[(c, d, p)] == 0:
                for t in range(num_teachers):
                    model.Add(x[(t, c, d, p)] == 0)

# (B) 老師不分身 (在某一節課，該老師最多只能教一個班級)
for t in range(num_teachers):
    for d in range(num_days):
        for p in range(num_periods):
            model.AddAtMostOne(x[(t, c, d, p)] for c in range(num_classes))

# (D) 滿足學科要求總節數
for c in range(num_classes):
    for t, req in teacher_requirements.items():
        model.Add(sum(x[(t, c, d, p)] for d in range(num_days) for p in range(num_periods)) == req)
MODULE 04 高級邏輯與指示變數 (Indicator Variables)

處理進階與連堂限制

這是本代碼最精彩的部分，展示了如何用數學方式表示複雜邏輯。

(1) 資源課與參觀課的集中化： 為了防止老師每天都在排課。我們建立了一個 day_active 的輔助變數（布林）。 如果當天有上課，則 day_active[d] 被強迫設為 1（因為 sum(x) <= 100 * day_active）。如果當天沒上課，則必為 0。 最後我們要求 sum(day_active) <= 2，這表示這些活動在一週內只能發生在其中的某兩天。

(4) 生活課連堂逻辑： 這利用了 OnlyEnforceIf 機制。當我們建立 is_pair 變數，它能控制當前這一節和下一節課是否被同時觸發。這是一種非常實用的「布林開關」技巧。 

# (1) 資源課與參觀課兩天內集中上完
for t in [5, 6]:
    day_active = [model.NewBoolVar(f'active_t{t}_d{d}') for d in range(num_days)]
    for d in range(num_days):
        # 大 M 法 (Big M Method)：確保 sum(x) > 0 時，active 必為 1
        model.Add(sum(x[(t, c, d, p)] for c in range(num_classes) for p in range(num_periods)) <= 100 * day_active[d])
        model.Add(sum(x[(t, c, d, p)] for c in range(num_classes) for p in range(num_periods)) >= day_active[d])
    model.Add(sum(day_active) <= 2)

# (4) 生活技能課 (t=3) 連續兩節課堂 (連堂)
for c in range(num_classes):
    for d in range(num_days):
        # 是否當天有生活課
        has_life_lesson = model.NewBoolVar(f'has_life_{c}_{d}')
        day_lessons = sum(x[(3, c, d, p)] for p in range(num_periods))
        model.Add(day_lessons == 2 * has_life_lesson)
        
        pair_vars = []
        for p in range(num_periods - 1):
            is_pair = model.NewBoolVar(f'pair_{c}_{d}_{p}')
            # 如果這兩節相鄰課連著上，則強迫 x[p] + x[p+1] == 2
            model.Add(x[(3, c, d, p)] + x[(3, c, d, p+1)] == 2).OnlyEnforceIf(is_pair)
            
            not_pair = model.NewBoolVar(f'not_pair_{c}_{d}_{p}')
            model.Add(x[(3, c, d, p)] + x[(3, c, d, p+1)] <= 1).OnlyEnforceIf(not_pair)
            model.AddExactlyOne([is_pair, not_pair])
            pair_vars.append(is_pair)
        
        # 確保當天若有課，必須且只能構成一組連堂
        model.Add(sum(pair_vars) == has_life_lesson)
MODULE 05 求解與結果解譯輸出

執行引擎與結果解析

最後，我們實例化 CpSolver。因為排班問題有時是 NP-hard，為了防止程序無止境地卡住，通常我們會設定時間上限。

在成功尋求到可行解後，我們必須使用 solver.Value() 來提取最終布林變數的值（它會返回 0 或 1），而不能直接讀取變數對象。 

solver = cp_model.CpSolver()
# 設定超時保護機制：1分鐘
solver.parameters.max_time_in_seconds = 60.0
status = solver.Solve(model)

if status == cp_model.OPTIMAL or status == cp_model.FEASIBLE:
    print("【成功排定課表！】")
    # 利用 solver.Value(x[(t, c, d, p)]) 檢查最終被分配為 1 的變數並呈現課表
else:
    print("無法找到滿足所有條件的課表（無解），請檢查約束條件是否相互衝突。")

自我檢測：5 道概念複習題

測試您對 CP-SAT 的理解程度，點擊題目以顯示答案與深度代碼解析。

答案：代表一個「時空排定決策開關」。

當該布林值經求解器確定為 1 (True) 時，表示「老師 t 在第 d 天的第 p 節，被指派去教 c 班級」。若為 0 (False) 則表示不教。整個排課表的過程，實質上就是在尋求這個矩陣的最佳 0/1 分佈。

答案：語意上是等價的，但底層引擎的優化效率大不相同。

AddAtMostOne 是 OR-Tools 針對「至多只有一個為 True」的情境專門設計的約束。底層 SAT 引擎會直接將其翻譯成高度優化的 2-SAT 克勞斯（Clauses）或一組邏輯門結構，其搜索與剪枝效率遠高於通用的代數不等式加和 Add(sum(...) <= 1)。

答案：為了維持常規的 4D 矩陣結構完整性，方便統一進行群體約束運算。

如果在建立 x 字典時直接排除 class_available 為 0 的鍵，那麼我們在後面實行 sum(x[(t, c, d, p)] for c in range(...)) 等操作時，就會頻繁遇到 KeyError，需要寫大量繁瑣的 if key in x 判斷式。透過將其指派為硬性條件 x == 0，既能利用求解器自動簡化排除，又能保持代碼邏輯的簡潔優雅。

答案：它是條件限制（Implication / 蘊含邏輯）在 OR-Tools 中的具體實現。

當我們宣告 model.Add(A == B).OnlyEnforceIf(is_pair) 時，其代表的數學意義是：
is_pair ⇒ (A == B)
意即當 is_pair 布林值為 1 時，該等式限制必須被強烈執行；如果為 0，這個約束就不會被觸發，允許 $A \neq B$。這可以讓程序靈活地控制哪些限制在何時生效。

答案：這關係到是否存在「目標函數（Objective Function）」以及是否已被證明為最優。

  • FEASIBLE (可行解)：代碼中所有的 model.Add(...) 限制均被滿足。但因為您的代碼中沒有設置目標函數（例如：沒有調用 model.Minimize(...) 或 model.Maximize(...)），所以對求解器而言，任何一個滿足條件的課表都是好課表，回傳的均是可行解。
  • OPTIMAL (最優解)：當我們宣告了目標優化目標，且求解器能在數學上「證明」沒有比當前解更優秀的解存在時，返回此狀態。如果沒有目標函數，有時求解器在完成全域空間掃描後，也會直接回傳 OPTIMAL。

創意挑戰：5 道實戰擴充題

排班最大的挑戰是面對源源不斷的「新需求」。請發揮您的編程實力，思考並嘗試實現以下擴充！

挑戰一：老師每日最高課時限制

實戰難度：★★☆☆☆

情境描述：為了避免老師過度疲勞，規定任何一位老師，在同一天（d）內最多只能上 3 節課。

思路提示：
固定老師 t 與天數 d，對所有班級 c 與節數 p 進行加總，限制其和小於等於 3。 
# 限制每位老師每天最多3節課
for t in range(num_teachers):
    for d in range(num_days):
        model.Add(sum(x[(t, c, d, p)] 
            for c in range(num_classes) 
            for p in range(num_periods)) <= 3)
挑戰二：實體專用教室預約衝突

實戰難度：★★★☆☆

情境描述：學校只有一間「生活技能室」。因此，所有班級的生活課（t=3）在同一時間段 (d, p) 內，最多只能有一班在使用該教室。

思路提示：
鎖定科目 t=3，在任何特定的 (d, p)，全體班級 c 的決策值加總必須小於等於 1。 
# 確保同一個時段只能有一班上生活課(t=3)
for d in range(num_days):
    for p in range(num_periods):
        model.AddAtMostOne(x[(3, c, d, p)] for c in range(num_classes))
挑戰三：核心科目分散原則

實戰難度：★★★☆☆

情境描述：為了保證學生學習吸收效果，規定同一班級（c）在同一天（d）內，中文課（t=0）和英文課（t=1）不能重複上兩堂（意即中文每天最多1節，英文每天最多1節）。

思路提示：
對每個 c、每個 d，及學科 t ∈ {0, 1}，對所有節數 p 進行加總，限制上限為 1。 
# 限制中英文主科每天最多上1節
for c in range(num_classes):
    for d in range(num_days):
        for t in [0, 1]:  # 中文、英文
            model.Add(sum(x[(t, c, d, p)] for p in range(num_periods)) <= 1)
挑戰四：偏好優化：導師課時段（軟限制）

實戰難度：★★★★☆

情境描述：宗教學科（t=4）的老師極其希望不要把他的課排在每天的最後一節（p=5）。這不是一個強制性的物理限制，而是一個「偏好（Preference）」。

思路提示：
這屬於「軟限制 (Soft Constraint)」，我們需要引入一個目標優化函數。對宗教課排在 p=5 的次數實施懲罰（Penalty），並調用 model.Minimize(...) 來最小化這個懲罰分。 
# 軟約束：宗教課(t=4)不希望排在最後一節(p=5)
penalties = []
for c in range(num_classes):
    for d in range(num_days):
        # 若在 p=5 排課，將會被計入懲罰
        penalties.append(x[(4, c, d, 5)])

# 設定優化目標：最小化違反宗教老師意願的次數
model.Minimize(sum(penalties))
挑戰五：合班共同參觀課（多維連動限制）

實戰難度：★★★★★

情境描述：學校為了節約資源，規定D 班和 E 班的「參觀課（t=6）」必須被安排在同一個時間段共同進行（因為這兩班要乘同一輛巴士去，由同一位參觀老師 t=6 帶領）。

思路提示：
這表示對於任何特定的時間 (d, p)，D班（c=3）被排參觀課與E班（c=4）被排參觀課的布林決策變數值必須完全相等（同為 0，或同為 1）。我們可以直接用等式 model.Add(x_D == x_E) 來綁定。 
# 將 D班 (c=3) 與 E班 (c=4) 的參觀課 (t=6) 時序同步
for d in range(num_days):
    for p in range(num_periods):
        # D班與E班在同一時間是否參觀，必須完全一致
        model.Add(x[(6, 3, d, p)] == x[(6, 4, d, p)])
